## Скидочные карты

GET /discountCard, строка 1276, response 200 ссылается на
DiscountCardsResponse. В DiscountCardItem указаны именно типы полей,
а не только примеры:

| Поле | Swagger | Наблюдаемый production |
|---|---|---|
| number | integer, строки 582–583 | string из цифр |
| is_default | boolean, строки 588–589 | integer 0/1 |
| start_date | string, строки 592–593; nullable не указан | null |
| end_date | string, строки 590–591; nullable не указан | null |
| DiscountCardsResponse.data | array, строки 601–602 | object с card в последнем прогоне |

Тестовые ожидания integer/boolean для number/is_default соответствуют
этому Swagger. Менять их на string/integer исключительно ради PASS нельзя.
Пользователь независимо подтвердил создание карты без дат в ВМ;
nullable даты оставлены в тестовой схеме как подтверждённое бизнес-поведение.
В документации этот случай не отражён и требует согласования представления
в API (например, nullable: true).

В DiscountCardItem отсутствует список required: Swagger описывает типы
представленных свойств, но не делает каждое из них обязательным.
Наличие start_date/end_date остаётся дополнительным ожиданием тестового
проекта, а не установленным этим Swagger требованием.
Формат дат date/date-time также не задан: формат нельзя выводить только
из примеров ISO-строк.

## Авторизация получения apiKey

GET /apiKey/byClinicCode содержит security: ApiKeyAuth, строки 725–726.
Схема ApiKeyAuth требует заголовок X-API-KEY, строки 10–15.
Наблюдавшаяся выдача непустого ключа без этого заголовка расходится
с указанной схемой безопасности, если она актуальна для проверяемого API.
Точный статус отсутствующего ключа для этого endpoint отдельно не описан;
ожидание 401/403 в тесте — проверка отказа, не точный Swagger response code.
