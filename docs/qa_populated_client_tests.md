## Подготовка эталонов

Секция populated_client уже добавлена в игнорируемый локальный файл
test-artifacts/qa-client-data.json. ID записей и значения нужно получить
из ВМ или другого независимого подтверждённого источника.
В populated_client.expected каждая коллекция задаётся объектом:

- confirmed_in_vm: true;
- complete: true только если перечислены все ожидаемые записи,
  иначе false (проверяются указанные записи, дополнительные допускаются);
- records: непустой список объектов с идентификаторами и хотя бы одним
  ожидаемым полем сверх идентификатора.

| Коллекция | Поля идентификации | Примеры дополнительных полей |
|---|---|---|
| admission | admission_id: string | admission_date, description, pet.alias |
| recomendation | id: string | content, date, petName, attachments_data |
| vaccination | medcard_id, vaccine_id, vaccination_date: string | name, pet.alias, date_nexttime |
| card | id: integer | number, pet_id, is_default, start_date, end_date |

Вложенные объекты сравниваются по указанным полям; список, если указан
в эталоне, сравнивается по длине, порядку и указанным значениям элементов.
Типы также сравниваются строго. Не заполняйте эталоны автоматически
из ответа проверяемого API: это скроет ошибки данных.

Для варианта смены скидочных карт нужен клиент с хотя бы одной картой.
Телефон клиента 1414 пока не предоставлен: независимая проверка
соответствия его телефона и ID в данном этапе не выполнялась.
